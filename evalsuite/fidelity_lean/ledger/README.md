# Ledger formalization fidelity

Evaluator-only. Hand an auditor **only Interface.lean**, with the ordinary report
and sources. Do not expose Reference, fixtures, generated material or truth. The
public API mirrors approvals: `emit(key, directory)`, `validate(material, runner)`,
`fixture(material, slip=None, wrong_item=False, constant=False, omit_item=False)`, and
`grade(material, candidate, runner, prove=False, proof_limit=1000)`. Use a distinct
retained directory under `tmp/` for each run. No campaign or model calls occur.
Use direct Lean 4.24.0 (`import Std`), never Lake. The injected runner is mandatory;
the shared trusted runner is only for generated programs and authored fixtures.

## Facts, rules, and independent truth

Facts preserve recorded amounts, corrected amounts, dates (Gregorian ordinals),
payees, approval markers, void status, budget and population. Approval resolutions
are separate from the recorded marker. Each sealed world is generated by the
original Cartesian completion, including all independent annex alternatives.
Annex alternatives can therefore produce duplicate operational worlds. Full
original facts, dates, annex fields, unknowns, worlds and input ordering remain
in `truth.json`. Dates use ISO strings in JSON and ordinals in Lean.

The seven-field rule result contains the sample total, signed total-minus-budget
gap, first largest entry and its amount, missing approval count/amount, recorded
present count and population missing count. The reference uses corrected amounts,
excludes voids, resolves unknown approvals, and adds the unknown unsampled count.
Python expectations reuse the generator's captured `quantity` and `live` closures;
no truth is inferred from verdict counts. The generator's first-in-list `max`
behavior is preserved on ties. The candidate uses a separately authored fold.

The key must exactly match regeneration, including generator version. The material
records the generator and reference SHA-256. `validate` compares every supported
claim's truth vector and sealed-world key counts/verdicts; it also recomputes the
Python key for every unsupported claim. `lean_checked_claims` and
`python_checked_claims` disclose this distinction. A rule vector element reports
whether **all seven fields** equal the Python oracle's summary for that world.
Rule fidelity is the fraction of matching worlds, not a per-field score. Lean
emits raw summaries through a strictly parsed protocol; Python compares them to
the oracle. Expected summaries are never embedded in candidate scoring programs.

## Unseen inputs: 870 rule worlds

The main grid has 864 worlds:

- Two ordered entries, amounts independently 0, 1 or 2 cents: 9 choices. The old
  ledger amount is `2 - amount`, exercising corrections upward, unchanged and
  downward. Equal amounts exercise stable ranking ties.
- First entry always live; second live or voided: 2 choices.
- Each approval is present, absent, unknown resolved present, or unknown resolved
  absent: 16 paired choices. Unknown markers remain unchanged after resolution.
- Three positions jointly choose budget offsets -1, 0, +1 relative to the live
  total (clamped at zero) and unsampled missing counts 0, 1, 2, with two unsampled
  population entries. This covers each boundary without the full Cartesian
  product between budget offsets and unsampled counts.

Six supplemental worlds cover unsampled capacity 0, 1 and 2, and every count from
zero through that capacity. They have two sampled entries, one absent approval,
so they also expose half-integer sample-rate extrapolation and ties-to-even
rounding. All worlds have distinct IDs and at least one live entry. Caps are 1,000
rule worlds and 2,000 inputs per claim; exceeding either fails rather than truncates.

Each supported claim is tested on all sealed worlds and all 870 rule worlds,
renamed to its target and another dossier ID. Additional worlds put the measured
quantity at the claim's stated value and both nonnegative neighbors. Count claims
get enough rows to reach those counts. Gap claims also get negative, zero and
positive signed differences. Largest-payment probes independently vary the target
and competing entry around the stated amount, including ties in both row orders.
Thus constant answers, wrong-entry claims and claims omitting identity cannot hide
behind unchanged dossier facts. Bounds are inclusive (`>=`); exact claims
use equality, and signed budget differences use `Int`, avoiding truncated natural
subtraction. Negative stated counts remain representable and always fail when
appropriate. This is a bounded test, not every possible combination of facts.

The ledger has **no operational date/period rule or fixed numerical threshold**:
its dates are source metadata, and cutoff approval status is already supplied as
an input. It does not compute elapsed days or infer post-cutoff approvals from the
annex. There is therefore no calendar boundary to invent. Numerical boundaries
here are equality, ranking, signed budget direction, and each claim's count/amount
bound, all exercised on both sides where the nonnegative domain permits.

## One-rule variants and candidates

`fixtures/Faithful.lean` supplies the independent rule. `fixtures/Slips.lean`
supplies ten independent variants, selected by `fixture(slip=...)`:

| Variant | Single rule bent / generator error motivation |
| --- | --- |
| `includesVoided` | Include void rows in the sample; `includes_voided_entry`. |
| `supersededAmount` | Use old amounts in all amount calculations; `uses_superseded_amount`. |
| `unknownAsAbsent` | Treat an unknown approval as absent regardless of resolution; `asserts_unknown_as_fact`. |
| `unknownAsPresent` | Treat an unknown approval as present regardless of resolution; `treats_unknown_as_settled`. |
| `unsampledIgnored` | Use sample missing count as the population count; scope/bound errors. |
| `extrapolatesSampleRate` | Extrapolate recorded absences to population, ties-to-even; `extrapolates_sample_rate`. |
| `reversedDirection` | Negate the signed budget difference; `reversed_direction`. |
| `arithmeticSlip` | Add one cent to the sample sum (and its derived gap); `arithmetic_slip`. |
| `missingSheetAsPresent` | Count unknown markers as recorded Present; `treats_missing_sheet_as_present`. |
| `wrongEntry` | Choose the smallest rather than largest payment; `wrong_entry`. |

Wrong stated values, overstated bounds and unsupported documentary errors are
claim mutations, not separate rule engines. Original predicates handle both
report variants independently, with report-qualified claim IDs. Strength must be
10/10 before any candidate grade is returned. Claim fidelity counts claims that
agree on **every** input, not the fraction of individual true/false coincidences.

## Claim coverage and fail-closed exclusions

Graded: `sample_total`, `budget_gap`, `largest_payment`,
`sample_missing_approvals`, `sample_missing_approval_amount`, `recorded_approvals`,
`population_missing_approvals`.

`recorded_approvals` is marked nonformal by the generator but has a genuine test
of the recorded table markers. It is graded as a representation test, not proof
that Lean read a document. Unknown resolution does not turn its marker into Present.

Unsupported:

- `payment_lookup`: the Python predicate closes over the original `entry` and
  ignores `w`. Substituting a sensible world lookup in Lean would disagree with
  that oracle under changed facts; imitating its constant would falsely imply
  lookup fidelity. Fix the generator predicate before adding this claim kind.
- `annex_scope`: document inclusion assertion outside this operational interface.
- `annex_content`: document text assertion; no operational rule in this family
  can establish what the annex says or whether it was supplied.

Across seeds 511 and 512, indices 1–5 (10 dossiers, both reports), **140/180 claims
are graded: 77.7778%**. Unsupported rows have an explicit reason, no Lean spec,
`status: unsupported`, `rate: null`, and `agrees_everywhere: false` even for the
faithful fixture. `claim_fidelity` explicitly covers supported claims;
`all_claims_fidelity` includes unsupported claims as failures and cannot reach
100%. The faithful supported score must be paired with the reported coverage.

## Validation and limits

Run the local unittest module with Python 3.12. Lean tests explicitly skip unless
`AUDIT_TEST_LEAN` names a binary. On the approved host use the coordinator's
`remote-test.sh step3-ledger` command. The tests regenerate ten dossiers from two
seeds, grade faithful candidates, distinguish every slip, reject wrong-item and
constant claims, check malformed outputs and drift, and request one kernel proof.

The optional `by decide` proof compares candidate and reference on the complete
870-world bounded set and requires an axiom-free report. It is neither a universal
proof nor claim agreement proof. Larger sets receive an explicit proof skip reason.
Sources, outputs, hashes, execution times and JSON results remain in the run folder.

The operational rules translate faithfully to the supplied structured facts.
Limits remain: the corrected `amount` is already normalized by the generator,
not independently extracted from correction text; annex and lookup claims are
ungraded; population-denominator wording is not separately tested by the original
population predicate. Counterfactual input worlds are evaluator tests, not claims
that original source documents changed. Trusted-fixture execution is not protection
against malicious candidate output or file access. Future real-agent scoring needs
its own sandbox; reference code is included only for reference checks and proofs.

No shared core change is required. A future core extension should represent
non-Boolean rule outputs and unsupported claim coverage directly, rather than
having each family serialize raw summaries and unsupported coverage itself.
